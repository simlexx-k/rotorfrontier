# Contributing

Thanks for helping improve RotorFrontier.

1. Open an issue describing the player-facing problem or proposed system change.
2. Create a focused branch from `main`.
3. Keep simulation changes deterministic and avoid allocations in fixed-update loops.
4. Add or update tests and documentation for behavior changes.
5. Run `npm run lint` and `npm test` before opening a pull request.
6. Include manual verification notes, browser/controller coverage, and screenshots
   for interface changes.

Do not commit credentials, private signaling codes, generated build output, or
licensed third-party assets without clear redistribution rights. Keep combat content
fictional and avoid real-world operationally sensitive data.
